## How to Use the Printing Press

### Important: Must Run Interactively
The `printing-press` binary **cannot** be run from inside an agent's sandbox session. It must be invoked by the user in their own Claude Code terminal session. The `/printing-press` skill drives the binary interactively through a research → generate → build → shipcheck loop.

### Starting a Session
```powershell
cd C:\Personal\cli-printing-press
claude --plugin-dir .
```

Inside that Claude Code session:
```
/printing-press <AppName>
```

Alternatively, if skills are installed globally:
```powershell
claude   # from any folder
/printing-press <AppName>
```

### Update the Press
```powershell
cd C:\Personal\cli-printing-press
git pull
go build -o ./printing-press ./cmd/printing-press   # rebuild local binary
```

## Key Architecture Notes

### Why CLIs Win for Agents
- **100x fewer tokens** than MCP tool definitions
- **`--compact` flag** drops to high-gravity fields only (60-80% token reduction)
- **Auto-JSON when piped** — no `--json` flag needed
- **Typed exit codes** — `0=success`, `2=usage`, `3=not found`, `4=auth`, `5=API`, `7=rate limited`
- **Local SQLite** — `sync` once, then `search` in 50ms with no API round trip

### PP CLI Pattern Check (when to generate a CLI before writing a skill)
1. Skill makes >2 calls to the same API per workflow run
2. Skill paginates manually through large result sets
3. Skill needs to filter/join data across resources
4. Skill's token output is dominated by raw API JSON

### Skill Output Location
Generated CLIs land in:
- Binary: `~/printing-press/library/<api-slug>/<api-slug>-pp-cli.exe`
- Skill companion: inside the library folder, then symlink to `~/.claude/skills/`

### Community Library
Browse pre-built CLIs at `C:\Personal\printing-press-library` or online at printingpress.dev.
